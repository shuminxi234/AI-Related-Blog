Jelly UI 源码解析：当原生表单控件拥有软体物理

按钮按下时向指尖凹陷，松手后像果冻一样回弹；滑块被拖动时，边缘会产生局部形变。这类效果通常只出现在品牌展示页，因为一旦进入真实表单，就要同时处理键盘、焦点、提交、校验和无障碍语义，视觉实验很容易变成维护负担。 Jelly UI 尝试把两者放在同一个组件里：前景仍是真实的表单控件，背景则由 Canvas 绘制软体表面。项目目前以 Web Components 形式提供，运行时没有第三方依赖，使用一个 ESM 入口即可注册组件。需要先纠正一个容易产生的误解：它并非只靠 CSS transition 做弹性缩放，而是用 TypeScript 实现物理模拟，构建后由 JavaScript 驱动 Canvas 2D 绘制。 五分钟接入：不是替换 CSS 类名 最直接的试用方式是加载官方托管入口，然后使用 jelly-* 自定义元素： <script type="module" src="https://jelly-ui.com/package.js"></script> <jelly-theme mode="auto" accent="#7c3aed"> <form id="profile-form"> <jelly-input name="email" type="email" label="邮箱" placeholder="you@example.com"> </jelly-input> <jelly-switch name="notice" checked>接收通知</jelly-switch> <jelly-button type="submit" variant="mint">保存</jelly-button> </form> </jelly-theme> const form = document.querySelector('#profile-form'); form.addEventListener('submit', (event) => { event.preventDefault(); console.log(Object.fromEntries(new FormData(form))); }); 这里不是给已有 <button> 添加一个 class，而是使用 Custom Elements。官方入口会重新导出构建产物 dist/jelly.js，后者注册全部组件。生产环境若不希望依赖第三方域名，可以按照仓库说明执行 npm run build，再把 package.js 与 dist/ 一并部署到自己的静态资源域名。 ...

开源 AI 追上闭源了吗？Mozilla 2026 报告的答案与工程现实

“开源模型已经追上闭源模型”是一个很有传播力、也很容易误导工程决策的结论。Mozilla 在 2026 年 7 月发布首份 《The State of Open Source AI》 后，这种说法再次流行起来。报告确实给出了一个醒目的数字：在 Chatbot Arena 的统计口径下，领先闭源模型与开放模型之间的平均能力差距约为 3.3 个百分点。 但报告更重要的结论不是“所有场景已经平手”，而是：模型是否开放，已经不再是能力高低的可靠代理变量；真正拉开生产效果的，正在变成模型之外的工程系统。 先弄清楚：3.3 个百分点代表什么 报告用 Chatbot Arena 的数据回顾了约两年的变化：闭源模型相对开放模型的领先幅度，从 2024 年初的 8.04% 一度缩小到 0.5%，截至 2026 年 3 月约为 3.3%。这个数字说明开放模型已经进入前沿竞争区，但不能理解为每项能力都只差 3.3%。 Mozilla 自己把当前格局称为“参差不齐的前沿”（jagged frontier）： 在编码、指令遵循和通用知识上，开放模型已达到或接近领先水平； 在推理、长上下文检索和 Agent 任务上，闭源模型仍有优势； Chatbot Arena 衡量的是特定环境中的用户偏好，不能替代企业自己的准确率、延迟、稳定性和安全评测。 因此，“开源是否够用”已经不是一个抽象问题。客服摘要、代码补全、文档抽取与自动执行交易的 Agent，需要的是完全不同的能力边界。平均分只能用于观察趋势，不能直接成为采购依据。 这里还要区分“开源”与“开放权重”。许多模型允许下载权重，却没有公开训练数据、完整训练代码或全部对齐过程，许可证也可能限制商业用途。报告讨论的对象同时包含 open source 与 open weight；团队做合规审查时，不能因为权重可下载就默认它符合传统开源定义。 采用率很高，生产转化却仍落后 报告采用了 Mozilla 委托 SlashData 开展的在线调查。附录显示，调查在 2026 年 5 月 19 日至 29 日进行，覆盖 1,494 名符合条件的开发者，并按地区加权。受访者都在应用中使用开放或闭源模型添加 AI 功能，因此这些数字描述的是 AI 实践者，而不是全体开发者。 ...
