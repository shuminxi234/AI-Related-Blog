Kimi K3 技术拆解：2.8T MoE、KDA 与 Attention Residuals 意味着什么

Moonshot AI 于 2026 年 7 月 16 日公布 Kimi K3。官方给出的几个数字很醒目：2.8 万亿总参数、原生视觉能力、1,048,576 token（约 100 万 token）上下文，以及每个 token 在 896 个专家中激活 16 个。比“3T 级模型”这个标签更值得关注的，是 K3 如何同时处理三个互相牵制的问题：扩大模型容量、控制单次推理计算量，并让超长上下文仍具备可接受的效率。 本文不把尚未公开的细节当作定论。K3 的完整权重预计最迟于 7 月 27 日发布，因此当前可以核验的是官方技术博客、已经公开的 KDA 与 Attention Residuals 论文，以及在线 API；许可证、权重格式和真实部署成本仍应以届时的模型卡为准。 2.8T 不等于每次推理都计算 2.8T 参数 K3 采用 Mixture of Experts（MoE）架构。可以把专家层理解为一组并行的子网络：路由器根据当前 token 选择少数专家参与计算，而不是让所有专家同时工作。官方将 16/896 的稀疏激活与 Stable LatentMoE 框架一并描述；每个 token 有效激活其中 16 个专家。 这带来两个不同维度的规模：总参数量代表模型可容纳的知识与功能容量，激活路径决定一次前向计算的主要成本。因此，不能用稠密模型的方式，把 2.8T 直接等同于每个 token 的计算量；同样也不能简单按 16 / 896 乘总参数，推导出精确的激活参数，因为嵌入、注意力、共享层和路由结构并不一定属于独立专家。 MoE 省的是计算，不会让存储与通信问题消失。完整权重仍需分布到大量设备，推理时还会发生 token 路由和专家间通信。对于多数团队，K3 更现实的使用方式仍是 API 或托管推理，而非办公室里的单机部署。“开放权重”提供了研究、微调和自建服务的可能，不代表部署门槛已经变低。 ...
